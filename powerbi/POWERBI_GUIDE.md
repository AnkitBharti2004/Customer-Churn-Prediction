# Power BI dashboard guide (separate from the Streamlit app)

Power BI Desktop is free (Windows). Power BI has no connection to the Python models;
it analyses data files. Two files are generated by `python churn_prediction.py evaluate`:

| File | Use |
|---|---|
| `reports/powerbi_customers.csv` | All cleaned customers + `TenureGroup`, `ChurnLabel`, `Churn` (0/1). Use for every business KPI. |
| `reports/test_set_predictions.csv` | Model probabilities for the held-out test customers only (about 20% of rows). Use for "predicted risk" visuals. |

## 1. Import and clean
1. Power BI Desktop > **Get data > Text/CSV** > choose `powerbi_customers.csv` > **Transform Data**.
2. Check types: `tenure`, `MonthlyCharges`, `TotalCharges` = Decimal Number; `Churn` = Whole Number; text columns = Text.
3. `TotalCharges` has 11 blank rows (new customers, tenure 0). Leave them blank or **Replace Values** null -> 0; do not delete rows.
4. Rename the query `Customers`. Optionally import `test_set_predictions.csv` as `TestPredictions` and relate `customerID` (one-to-one) to `Customers[customerID]`.
5. Sort `TenureGroup` by column: add a helper column in Power Query `TenureOrder` (1-4) or keep the text labels, which already sort correctly.

## 2. DAX measures
```DAX
Total Customers = COUNTROWS(Customers)
Churned Customers = CALCULATE(COUNTROWS(Customers), Customers[Churn] = 1)
Active Customers = CALCULATE(COUNTROWS(Customers), Customers[Churn] = 0)
Churn Rate % = DIVIDE([Churned Customers], [Total Customers], 0)

Avg Monthly Charges = AVERAGE(Customers[MonthlyCharges])
Avg Monthly Charges (Churned) = CALCULATE([Avg Monthly Charges], Customers[Churn] = 1)
Avg Monthly Charges (Active)  = CALCULATE([Avg Monthly Charges], Customers[Churn] = 0)

-- Historical: monthly recurring revenue that left with churned customers
Monthly Revenue Lost = CALCULATE(SUM(Customers[MonthlyCharges]), Customers[Churn] = 1)
Monthly Revenue Lost % = DIVIDE([Monthly Revenue Lost], SUM(Customers[MonthlyCharges]), 0)

-- Predictive (test-set customers only): monthly revenue of customers the model flags as likely to churn
Predicted Monthly Revenue at Risk =
CALCULATE(SUM(TestPredictions[MonthlyCharges]), TestPredictions[PredictedChurn] = 1)
```
**Definition note:** "Revenue at risk" here means *monthly charges*, not lifetime value, and the predicted version covers only the test sample. State this on the report page.

## 3. Visuals
| Visual | Fields |
|---|---|
| 5 KPI **cards** | Total Customers, Churned Customers, Active Customers, Churn Rate %, Monthly Revenue Lost |
| **Clustered column** - churn by contract | Axis `Contract`, Values `Churn Rate %` |
| **Column** - churn by tenure group | Axis `TenureGroup`, Values `Churn Rate %` |
| **Bar** - churn by payment method | Axis `PaymentMethod`, Values `Churn Rate %` |
| **Clustered column** - monthly charges vs churn | Axis `ChurnLabel`, Values `Avg Monthly Charges` |
| **Donut** | Legend `ChurnLabel`, Values `Total Customers` |
| **Slicers** | `Contract`, `InternetService`, `TenureGroup`, `gender` |
Format `Churn Rate %` as percentage; add data labels; use red for churn, blue for active. Keep the page titles plain: "Churn overview".

## 4. Notes
- Re-run `python churn_prediction.py evaluate` and click **Refresh** if the CSVs change.
- These charts show associations, not causes.
- Do not publish real customer data to a public workspace. The IBM dataset is a public sample.
